# 上传范围（视频废案清理后）

源码、必要离线素材与已定版媒体分别列清单。上传清单只决定上传范围，不能作为本地删除依据。2026-10-19 已另按实际依赖完成视频废案整理，详见 [清理报告](../maintenance/视频废案清理报告.md)。

## Git 源码候选

现有产品源码与文档；最终视频 src、scripts、正式 SVG、配置、原依赖锁定文件、requirements.txt；必要素材的来源/摘要及原始验收证据。旧试听、播放器、阶段草稿、历史源码快照、重复备份和模型不再属于当前工程。

运行 `node tools/prepare-upload.js --write` 生成本地 upload-allowlist.txt 和 upload-scope-audit.json。工具不调用 add、commit 或 push。清单分为 selectedFiles、requiredProductionInputs 和 separateApprovedMedia；文件修改后需重新生成。只有 validationPassed 为 true 才生成白名单；检查失败返回非零退出码，不覆盖已有清单。

## 文档链接检查范围

上传工具遍历源码树内全部 Markdown，包括 marketing/video、brand、根 README 和 docs，要求当前本地链接的目标也在源码树内；文件仅在本地存在或已被忽略都不能算通过。未上传的 MP4 与封面以代码文件名和本地位置注明，不提供虚构的下载链接。

仅两份原始交付记录（production/evidence/2026-10-19 下的 score/README.md 和 sfx/README.md）保留历史相对路径与原字节；报告单列其文件摘要和历史引用数，不声称这些旧链接可用。请从[现行证据索引](../../marketing/video/production/evidence/2026-10-19/README.md)进入当前文件；该索引仍按当前文档检查。原机器验收 JSON 不改写。

## Git 字节保留

视频场景、原始证据、素材来源、依赖锁文件与定版清单由 .gitattributes 禁用自动换行转换。它们记录了逐字节 SHA-256，不能在上传或干净检出时被 LF/CRLF 转换改写。提交前核对 Git 暂存 blob 与这些受保护本地文件的摘要；普通产品源码与当前文档继续使用既有换行规则。

## 必要离线素材

选定原始演奏、批准 BGM、最终音效/混音分轨、16 个事件片段、必要旧 UI 对照、三份实际使用录音均保留。体积较大的 WAV/MP3 不混入 Git 源码候选，按 requiredProductionInputs 的逐文件 SHA-256 单独保存与传递；其中 public/audio/final-mix.wav 是完整时间轴的实际依赖。源码单独检出不带这些音频，不能据此宣称视频制作全部可复现。

素材当前路径和安装/修改命令见 [最小工程](../../marketing/video/production/README.md)。模型和 node_modules 已清理；依赖可按既有 lockfile 安装，选定音乐原件不可用 seed 或提示词替代。
